任务范围：S01–S12。目标：能围绕容量、延迟、公平性、成本和故障设计可落地的推理服务。

## 学习顺序

SLO → 请求生命周期 → 排队/容量 → 观测 → 部署/调度 → 故障与成本。先在清单中选择 P0，每次只推进一个可验证任务。以下案例是待实现任务书，尚无代码或实测结果；学习到对应任务时再创建目录。

## 独立案例任务书

| 计划目录（本模块 CaseStudy 下） | 条件 | 交付与验证 | 对应任务 |
|---|---|---|---|
| `01_bounded_queue/` | CPU / C++17 或 Python | 实现队列上限、阻塞/拒绝策略和优雅关闭；验证超时/取消路径。 | S02–03、F03 |
| `02_capacity_design/` | CPU / 文档与手算 | 根据输入输出长度和到达率，写容量假设、瓶颈和扩容阈值。 | S01–02、S11 |
| `03_incident_drill/` | 本地隔离服务或明确桌面推演 | 选 OOM/队列拥堵/客户端断连，记录现象、证据、修复、回滚和影响范围。 | S04–05、S12 |
| `04_deployment_plan/` | 文档；实测需相应环境 | 写固定版本部署、预热、灰度、失败回滚和资源请求；区分设计与已验证部署。 | S06–09 |

每个案例附运行命令、固定依赖、正确性检查与限制；报告用 [Experiment 模板](../Templates/Experiment.md)。没有对应硬件时保留实机验收，不将推导或模拟记作实测。

## 面试追问

- 客户端断连后 GPU 上已提交计算能立即取消吗？如何释放后续资源？
- 增加副本、增大 batch 和启用 TP 分别解决什么瓶颈？
- 多租户缓存共享如何兼顾收益和隔离？
