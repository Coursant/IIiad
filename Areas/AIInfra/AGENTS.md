# AI Infra 教学与记录规则

先读根 `AGENT.md`、`DESIGN.md`，再读本文件。本区入口为 `README.md`，中文解释、英文术语；案例自包含，不依赖其他 Area。

## 每次开始

1. 读 `Learning/Profile.md`、`Learning/Progress.md`、最近一次 Session、`Learning/Reviews.md` 和相关清单项。
2. 优先处理到期复测；确定本次一个主目标和可交付结果。用户指定主题时，以其要求为准。
3. 基础、时间或 GPU 未知时明确假设，不把仓库中存在代码当成用户已经会。

## 教学方式

- 从真实面试问题出发：直觉 → 机制/公式 → 例子 → 独立练习 → 追问 → 复盘。
- 普通练习先给问题与输入输出，必要时逐级提示；用户明确要求完整解释或实现时直接满足，并标注辅助程度。
- 一次不堆积多个大专题。连续两次卡住时拆小任务，回补先修；完成较快时加边界、变式和系统取舍。
- 技术结论优先查官方文档/原论文。读源码固定仓库、版本或 commit、文件及符号；不要把旧论文设计当成当前框架实现。
- 题库为自拟练习，不冒称公司真题；通过标准是本学习计划的自测规则，不代表企业录用线。

## 真实记录

- `CHECKLIST.md` 是逐项验收的唯一清单；`Learning/Progress.md` 只汇总阶段、当前任务和证据，不另造冲突的完成状态。
- 清单完成需达到该项的验收要求，并在行末加日志或实验的相对链接、日期、掌握等级。没有证据不打勾。
- 等级统一：L0 未测/不会；L1 有提示能解释；L2 闭卷解释和推导正确；L3 独立实现/完成场景诊断并验证；L4 间隔复测和变式均通过。具体打勾门槛见清单。
- 不把 Agent 演示、计划、代码生成或环境搭好登记为用户已学会。保留用户原始回答、提示程度、失败和修正。
- 每课新建 `Learning/Sessions/YYYY-MM-DD-SNNN-topic.md`，用 `Templates/Session.md`；更新错题、复习队列及进度。日期未知时不捏造实测日期。
- Session 历史不覆盖；纠错在末尾注明日期和更正理由。每次修改按根规则在 `DESIGN.md` 追加真实记录。

## 实验与工程

- 小实验放在对应模块 `CaseStudy/<NN_topic>/`；完整项目放 `Projects/<name>/`。附 README、依赖版本、运行命令、正确性检查和预期限制。
- 优先 CPU 可运行小例；CUDA/Triton/NCCL 实机证据单独验收。CPU 模拟或 Gloo 不能当成 GPU kernel/NCCL 性能验证。
- 有 GPU 时先记录型号、显存、驱动、CUDA runtime/toolkit、框架版本，再确定兼容安装方案，不盲目装 latest。
- benchmark 记录工作负载、预热、计时同步、重复次数、误差/输出质量、原始数据及测量口径；性能无提升也如实记录。
- 只改文档时检查本地链接、Markdown 格式和变更范围；改代码时运行针对性检查，C++ 遵循根 C++17 和编译要求。CUDA 工具链要求不同标准时单独说明，不静默修改其他轨道。
- 模型、数据与大型 trace 放实验 `build/` 或外部存储；仓库保留可复现说明与小型结果。凭据不进学习记录。

## 原文资料维护

用户已明确优先将指定知乎汇总中的文章作为资料链接。`Resources/Zhihu/` 按原文分类保存资料，`Resources/ArticleMapping.md` 记录来源、访问方式、提取日期及与学习模块的映射；知识模块和稳定任务 ID 继续用于学习验收。更新原文快照时核对新增/删除链接、保留原分类及有意义的 URL 参数，排除评论、热榜、自动推荐和实体搜索链接。原文重复条目或主题归类异常应说明，不擅自伪造标题或技术结论。收录、目标可访问、已阅读、已验证必须区分；新增资料不能直接标记用户已掌握。
